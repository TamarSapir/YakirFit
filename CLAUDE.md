# Yakir fit — project notes for Claude

Personal-training app for coach Yakir and his trainees. Hebrew, RTL, dark sporty design, pill/round buttons. The user (Yakir's wife) is not a developer: reply in Hebrew, keep explanations simple, and tell her exactly what to do after each change (usually: re-upload the folder to Netlify).

## Live setup
- Hosting: Netlify, deployed by dragging this whole folder into the site's **Deploys** page. There is no build server and no git deploy.
- Backend: Firebase (Auth: email/password + Google; Firestore). Spark (free) plan. No Firebase Storage, no Cloud Functions.
- `config.js` holds the real Firebase config and `coachEmails`. **Never overwrite or blank it.** The coach email must match the one in the Firestore rules.
- The app is installed as a PWA on phones. `sw.js` caches the shell: **bump `CACHE` in `sw.js` (e.g. `yakirfit-v2`) on every release** or phones may keep the old version.

## Files
- `app.js` — the whole app (vanilla JS, no framework, no bundler). Render functions return HTML strings; one delegated `click`/`change`/`submit` handler dispatches on `data-act`.
- `base.css` + `extra.css` + `theme.css` — styles, concatenated in that order by `build.py`. `theme.css` is the current look (deep black, solid orange `.card.hero` blocks with black text and white `.stat` tiles inside, white "on" pills, Rubik headings) and overrides the tokens in `base.css`. Anything placed inside a `.hero` must read on orange (the `.hero ...` rules handle chips, buttons, bars, rings, inline colors).
- Motion: `afterRender()` (wraps `render`) animates only when the screen changes (`screenKey`: role/tab/selected trainee); same-screen re-renders after a save never animate. Top blocks stagger in (`.anim-in`), blocks below the fold reveal on scroll (`.rv` + IntersectionObserver), sheets slide up/down (`closeSheet` removes after the exit animation). All off under prefers-reduced-motion.
- `index.html` — **generated** by `python3 build.py` (inlines the CSS). Edit the CSS files / `build.py`, then run `build.py`. Don't hand-edit `index.html`.
- `firestore.rules` — security rules. Pasted manually into Firebase console → **Firestore Database** (not Realtime Database) → Rules. Keep it ASCII-only (Hebrew comments broke pasting once).
- `manifest.json`, `sw.js`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` (180px, iPhone home screen) — PWA. Icons = the orange dumbbell from the logo on the dark background. The app name stays "Yakir fit" (owner's choice).
- Logo (Yakir Levi): `logo-dark.png` (light text + orange dumbbell, for the dark app / login), `logo-mark.png` (same without the tagline, top bar), `logo-print.png` (dark text, for the white PDF). Generated from the original logo by recoloring.
- `README.md` — Hebrew setup guide.
- `build.py` also writes a demo copy to `../yakir-fit-demo.html` (delete it; not needed). Run it with `python -I build.py` (UTF-8 safe on Windows).

## Roles
- Coach = signed-in user whose email is in `coachEmails` (and in the rules). Coach goes straight to the trainer view; there is no role picker and the coach never uses trainee mode.
- Everyone else is a trainee. New trainee → join form → `members/{uid}` created → waits until coach approves (creates `coach/{uid}` with `approved: true`).
- Trainees must never see other trainees' data or the coach's schedule. This is enforced by `firestore.rules`, not just the UI. Any new collection needs matching rules.

## Firestore data model
- `pub/main` — coach's public settings: `days` (0=Sun…6=Sat), `from`, `to` ("HH:00"), `off` (["YYYY-MM-DD"]), `phone` (WhatsApp). Read: any signed-in user. Write: coach.
- `members/{uid}` — trainee-writable: `name, phone, goal, email, wants (personal|online, chosen at sign-up; only preselects the bill type in the coach's approval sheet), avatar` (small JPEG data URL), `features {log, water, food}`, `water {every, from, to}`, `logs [{d, ex, kg, reps, sets, fail?, failNote?}]`, `exNotes {exerciseName: text}` (trainee's own note per exercise), `vids [{id, ex, url, kind: cld|link, d, at, note}]` (online trainees' exercise videos), `body [{d, kg, waist, chest, hips, arm}]`, `food [{id, meal, text}]`, `requests [{id, date, time, note, status: pending|declined, at}]`, `renewReq`, `joinedAt`. Read/write: that trainee or coach.
- `coach/{uid}` — coach-only writes, trainee reads own: `approved, color, offline, bill (card|single|online, default card), rate (per-trainee price override), subStart (YYYY-MM), subPays [{m, paidDate, price}], fb {vidId: {score 1-10, text, at, d}}, card {size, start, price, paid, paidDate}, cardHistory [...], plan [{id, title, ex: [{id, name, sets, reps, kg, mus {p:[], s:[]}, note, video}]}], sessions [{id, date, time, by, st: came|missed|null, paid?, paidDate?, price?}]`.
- `photos/{id}` — `{owner, d, data}` (compressed JPEG data URL < 1MB). Read/delete: owner or coach. Create: owner or coach. Update: coach.
- `coach/settings` — the price list `{prices: {single, plan, online, cards: [{size, price}]}}`. Coach-only (covered by the coach rules). Not a trainee: every loop over `DB.coach` must filter (tList/planClients already do).
- Old videos: reviewed + older than 60 days are hidden from lists (`isOldVid`, "show all" toggle); scores stay. Files are never deleted by the app (Cloudinary deletion needs a secret, so it's manual in the Media Library). `cleanupBanner()` reminds the coach when 10+ such Cloudinary videos piled up since `coach/settings.cleanedAt`.
- `pub/main.cld {cloud, preset}` — optional Cloudinary unsigned upload (free plan) for online trainees' videos. Without it trainees paste a YouTube/Drive link.
- Billing: card = punch card; single = every session marked `came` is owed at `rateOf(t)` until marked paid; online = monthly subscription, every month from `subStart` without a `subPays` entry is owed. `owed(t)` / `payments()` / `incomeBlock` derive everything.
- "Plan only" clients (people who buy just a training plan): stored as `coach/{randomId}` with `planOnly: true, approved: false, name, phone, goal, price, paid, paidDate, createdAt, plan`. No members doc, not in `tList()`/schedule. Coach tab "תוכניות" (`trainerPlans`, `planClientView`, `pcSheet`, saved via `savePC`). Covered by the existing coach rules, no rules change needed. Paid plan sales count in the monthly income.
- "Offline" trainees (no app account) are created by the coach under a random id in both `members` and `coach` with `offline: true`; on approving a real sign-up the coach can merge an offline record into it.

## Conventions in app.js
- `T(id)` returns a merged, normalized trainee object (members + coach docs). Mutate it, then `save(t, 'field1', 'field2')` — `save` routes each key to the right doc via the `MK` / `CK` lists and writes with `set(..., {merge: true})`. Arrays are replaced whole. New fields must be added to `MK` or `CK`.
- Card usage = sessions with `date >= card.start`. Attendance from `st`. Achievements/streaks computed in `achievements(t)` (no stored state; "seen badges" in localStorage).
- Without a valid `config.js` (or when Firebase scripts fail) the app runs in **demo mode** with a localStorage fake backend (`seedDemo`). Keep demo mode working: it is how changes are previewed.
- Muscles (`MUS`) include `glutemed` (ישבן צידי) and `adductors` (מפשעות). `MUS_RULES` is ordered: specific exercises first (adduction/abduction machines, single-leg RDL, Bulgarian split squat, chest-supported row, hip thrust), generic rules after — a new specific rule must go above the generic one that would also match. `EX_LIB` = name suggestions (datalist) in the exercise editor.
- Coach invite: "הזמנת מתאמן" in the trainees tab (`inviteSheet`) sends the app URL (`appUrl()`) over WhatsApp, to a number or via WhatsApp's contact picker.
- Live workout (Hevy-style): `members.live` = the workout in progress `{id, dayId, title, start, by, extra[], ex:[{id, name, note, cnote, sets:[{kg, reps, done, note, cnote, fail}]}]}`. `note` = trainee, `cnote` = coach (shown as "יקיר: ..."). Started from the plan by the trainee or by the coach from the trainee's profile (`ui.aw`, coach uses `ui.awFor`). Inputs save on `change` without re-render; `render` keeps focus on the focused set input. On finish (`finishWorkout`) only ✓ sets are kept: the workout goes to `members.wos` (last 60) and every ✓ set becomes a `logs` entry `{sets:1, wo:<id>}` — analytics (volume, records, muscle map) still read `logs` only. Deleting a workout removes its `wos` entry and its `logs` (`wo` id).
- `wos[].extra` / `live.extra` = muscles the coach marked by hand; `musFrom` gives each 12% of the base so they show on the body map.
- After finishing: `renderSummary` shows 3 share images drawn on canvas (1080x1920, logo-dark.png at the bottom: stats / month calendar / body map + last 7 days) shared via `navigator.share` files; `sumText` = copy-text version. `weekStripBlock` = the week strip (trainee progress tab + coach's trainee profile).
- Sets may carry `warm` (warm-up: shown as "ח", never written to `logs`, excluded from volume/records/"previous"), `rpe` (6-10), `fail`, `note`/`cnote`. Notes on finished sets are editable afterwards from the workout detail (`woSet`), which also syncs the matching log's `fail`/`rpe`.
- `suggest(t,name)`: progressive overload — if every working set of the last workout hit the top of the plan's rep range without failure, suggest +1 / +2.5 / +5 kg (5 for lower body ≥40kg). Plan exercise `ss: true` = superset with the previous exercise (auto rest timer skips between them).
- Coach templates: `coach/settings.templates [{id, name, plan, at}]` (save/load from the "תבניות" pill in any editable plan; listed on the plans tab; usable when creating a plan-only client).
- Weekly check-in (online trainees): `members.checkins [{wk (week start), d, sleep, energy, food (1-5), kg, note}]`, coach reply in `coach.ckfb {wk: {text, d}}`. A weight in a check-in is also written to `body`.
- Challenge: `pub/main.ch {id, title, goal, from, to, board:[{n (first name + initial), c, k}]}`, trainees opt in with `members.chJoin`. Trainees can't read each other, so the coach's app computes the board (`syncChallenge` on every coach render) and writes it to `pub` — only first name + count are exposed.
- Coach dashboard: `dashBlock` on the schedule tab ("השבוע במבט": idle 7 days, records this week, videos to review, new check-ins).
- Yakir's own training ("שלי" tab, `trainerSelf`): `members/{coachUid}` + `coach/{coachUid}` with `self: true, approved: false`, created by `ensureSelf()`. `approved:false` keeps it out of every trainee list, income and challenge. Same plan / live workout / week strip / records / body / photos as a trainee.
- Prices (`coach/settings.prices`): `{plan, online, fmt: {solo|pair|trio|group: {single, cards:[{size,price}], monthly:{1..5}}}}` (per participant). Old flat `single/cards` is read as `fmt.solo`. Deal per trainee on the coach doc: `bill` card|single|monthly|online, `fmt`, `freq` (monthly: sessions/week), `rate` (special price; for a card = whole card), `disc` (%). `rateOf`, `cardPriceFor`, `dealText`. `monthly` and `online` both use `subStart`/`subPays` (`isSub`).
- Business tab has 3 sub-tabs (`ui.bizTab`): summary (`payRepBlock`, `incomeBlock`, `financeBlock` = per-trainee rows for the month: due / paid / open), prices (`bizPrices`), settings (`bizSettings`: payment links `pub.pay {paybox, bit}`, `pub.policy`, `pub.growth`, WhatsApp, hours, off days, Cloudinary, CSV/JSON export).
- Payment flow: trainee sees `payCard` when owing → pays via PayBox/Bit → "שילמתי" writes `members.payRep {at, d, amount}` → coach "התקבל" (`payOk`) marks paid + WhatsApp receipt text (the receipt itself is attached by hand).
- Health declaration: `members.health {d, q:{heart,chest,dizzy,chronic,meds,joints,surgery,preg,doctor}, detail, exp, sex, avail, name, sig (jpeg data URL), by}`; paper: `coach.hpaper`. Filled from the pending screen, a banner, or by the coach on his device.
- Health questions are editable by the coach (עסק ← הגדרות): `pub.hq [{k, q}]` (empty/missing = the 9 defaults in `HQ`). Each declaration stores a snapshot `health.qs [[k, q]]` so old answers keep their wording. `healthPdf(t)` draws an A4 PDF with logo-print.png (blank with the trainee's name, or filled with answers + signature); a returned paper/PDF form is marked with `coach.hpaper = 'YYYY-MM-DD'`.
- Policy `pub.policy {cancel, hours, charge, fixed, weeks, wait}`. Trainee cancels → `members.cancels [{sid, at, late}]` → the coach app (`processCancels`) removes the session or marks `st:'late'` (counts on the card / is billed). Fixed slots: `coach.fixed [{dow, time}]`, generated ahead by `syncFixed` (skips off days, `fixedSkip`, card limit). Waiting list: `pub.busy` = ARRAY of 'date|time' (never a map: merge-writes keep stale map keys and loop) + requests with `status:'wait'`.
- Optional trainee features (`features.rm/cmp/report/nutri/habits`, off by default): 1RM (`rmBlock`, Epley + strength levels by sex from the health form), photo compare slider + share image, monthly report image (`reportImage`), nutrition `members.eat [{d,n,k,p}]` vs `coach.macro {kcal,prot}`, habits `members.habits {list, log:[{d,id,v}]}`. Periodization: `coach.cycle {on, weeks, step%, deload, dpct, start}` → `adjKg`.
- Coach exercise library `coach/settings.exlib [{name, mus, video, note}]` (autofills the exercise editor). Growth (`pub.growth {ref, gift, rev, after}`): referral link `?ref=uid` → `members.ref`, gift tracked in `coach.refGiven`; reviews `members.review {stars, text, ok, d}`.
- Group classes (optional, `pub.grp {on, list:[{id,title,dow,time,cap}], skip:['date_gid']}`): weekly classes, off days skipped. Sign-ups live in their own collection `gsign/{date_gid_uid}` = `{o: uid, k: 'date_gid', d}` (ids only, no names) so trainees can count free spots; rules let a trainee create/delete only his own doc. Listener starts only when `grp.on` (`ensureGs`). Coach marks "הגיע" → a normal session `{by:'grp', gk}` (counts on card/billing; hidden from the personal day list).
- Cancel: policy on → trainee sees the policy, free/charged; charged → "לדבר עם יקיר" WhatsApp. Policy off → request `cancels [{sid, at, ask:true}]` stays until the coach decides (`cxAskBlock`: free / charge / keep). `processCancels` handles only non-ask entries. Every cancel ends with a WhatsApp message to Yakir.
- Broadcast `pub.msg {id, text, until}` → banner for every trainee (dismiss per device). Birthdays `members.bday` (join form, "הפרטים שלי", coach edit) → coach "ימי הולדת" list + trainee banner. Schedule tab also shows "ממתינים לתשומת לב" (no activity 10 days and nothing booked, `lastAct`) and "כרטיסיות שנגמרות" with WhatsApp renewal text. Add-to-calendar (`calSheet`: Google link or .ics with a 2h alarm) on future sessions and joined classes. Body block: metric switch (`ui.bodyM`).
- `firestore.rules` holds the real coach email (yakir17177@gmail.com), ASCII-only, ready to paste.
- Long sheets: only the first 8 children animate in (`.sheet>*:nth-child(n+9){animation:none}`), so nothing stays hidden if animations don't run.
- Workout = all `logs` of one date. Volume = kg x reps x sets (bodyweight moves with kg 0 use the latest `body` weight). Muscle share comes from `ex.mus` (primary 1, secondary 0.4) or `guessMus(name)` keyword rules. Records (`records(t)`): weight PRs per exercise + workout-volume PRs; badges derive from them.
- PDF export: `renderPlanPages` draws every page itself on a canvas (RTL Hebrew, logo, a card per exercise; narrow 600x960 phone-friendly pages, last page grows/trims to fit), then `buildPlanPdf` puts the JPEG pages into jsPDF (cdnjs, lazy-loaded) with clickable video/WhatsApp links. Don't go back to html2pdf/html2canvas: it produced blank PDFs on phones. Delivery: `navigator.share` with the file (works on iPhone); plain download only when share isn't available (blob links in a new tab are blank in an installed iPhone app). In-app preview shows the page images.
- Income (`incomeBlock`, top of the coach "עסק" tab): `payments()` = every card in `card`+`cardHistory` and every plan-only client with `paid && paidDate && price`, grouped by `paidDate` month. Nothing stored separately.
- The coach can log weights for a trainee too (+ button in the trainee's plan, same `logSheet`), so volume works for trainees without the app.
- Dates are local `YYYY-MM-DD` strings; times `HH:MM`.
- WhatsApp: `waLink(phone, text)` → `https://wa.me/972…`.
